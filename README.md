# h2v

h2v is a self-hosted VPN panel for Xray VLESS Reality and Hysteria 2. It ships a Go backend, a React admin UI, PostgreSQL migrations, systemd units, Caddy reverse proxy config, backup tooling, and subscription pages for end users.

## Requirements

- Ubuntu 22.04 or 24.04 with systemd
- A domain pointing to the server
- Root access for install/update/uninstall
- Open ports:
  - TCP `443` or `PANEL_PUBLIC_PORT` for the panel via Caddy
  - TCP `VLESS_PORT` for Xray Reality
  - UDP `HY2_PORT` for Hysteria 2
  - TCP `80` during ACME HTTP-01 certificate issuance

## Install

Use a published release tag. Avoid installing from `main` for production.

```bash
curl -fsSL https://raw.githubusercontent.com/ProstyGospody/h2v/v0.1.0/install.sh -o install.sh
sudo H2V_REF=v0.1.0 bash install.sh install
```

Before the first release tag is published, run from a full local checkout or make the development ref explicit:

```bash
curl -fsSL https://raw.githubusercontent.com/ProstyGospody/h2v/main/install.sh -o install.sh
sudo H2V_REF=main H2V_ALLOW_FLOATING_REF=1 bash install.sh install
```

For stricter source verification, pass `H2V_SOURCE_SHA256=<sha256>` or set `H2V_REQUIRE_SOURCE_SHA256=1`.

The installer pins Go, Node, Xray, and Hysteria versions. Xray and Hysteria downloads are checked with SHA256 before installation.

## Operations

```bash
sudo /opt/mypanel/install.sh update
sudo /opt/mypanel/install.sh geodata
sudo /opt/mypanel/install.sh reset-admin
sudo /opt/mypanel/install.sh backup
sudo /opt/mypanel/install.sh restore /opt/mypanel/data/backups/panel-YYYY-MM-DD-HHMMSS.sql.gz
sudo /opt/mypanel/install.sh uninstall
```

Backups are stored in `BACKUP_DIR` and retained for `BACKUP_RETENTION_DAYS`. Backup exports from the API include user subscription secrets; store them as secrets and do not attach them to tickets or chat.

Raw traffic samples in `traffic_log` are retained for `TRAFFIC_RETENTION_DAYS`.

## Configuration

Runtime config lives in `/opt/mypanel/.env`. Important production values:

- `PANEL_JWT_SECRET`: random, at least 32 characters
- `DB_PASSWORD`: non-empty PostgreSQL password
- `REALITY_PRIVATE_KEY` and `REALITY_PUBLIC_KEY`: generated by `xray x25519`
- `HY2_TRAFFIC_SECRET`: local stats/auth secret
- `HY2_OBFS_PASSWORD`: required when `HY2_OBFS_ENABLED=true`

`PANEL_ALLOW_INSECURE_DEFAULTS=true` is only for local development and must not be used in production.

## Threat Model

h2v assumes the panel backend listens on loopback and is published only through the installer-managed Caddy site. `/metrics` and `/hy2/auth` are private endpoints and should not be exposed by external reverse proxies. Admin API access requires a short-lived bearer token plus an HTTP-only refresh cookie. Subscription tokens are bearer credentials for individual users and should be rotated if leaked.

## Recovery

If config rendering fails, the database remains the source of truth and the scheduled reconciler retries core config rendering. If a backup import fails after it starts applying changes, the panel attempts to restore a snapshot of settings, users, and core configs.

If the panel service will not start:

```bash
journalctl -u panel.service -n 100 --no-pager
sudo /opt/mypanel/install.sh reset-admin
sudo systemctl restart panel.service
```

If Xray or Hysteria reject users, run:

```bash
sudo systemctl restart xray.service hysteria.service
```
